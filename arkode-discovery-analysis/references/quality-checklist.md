# Quality Checklist for Discovery Analysis

## Purpose

Use this checklist before delivering AS-IS + Gap Analysis documentation to ensure completeness, accuracy, and quality.

---

## Pre-Delivery Checklist

### Evidence & Sources

- [ ] **Transcripts uploaded and analyzed**
  - All discovery call transcripts reviewed
  - Key quotes extracted with quotation marks
  - Stakeholder names/roles verified

- [ ] **Industry template loaded** (if applicable)
  - Correct industry template referenced
  - Used as guide, not copied verbatim
  - Client-specific patterns identified

- [ ] **No invented content**
  - Every stakeholder name from transcripts
  - Every process step has evidence
  - Every pain point quoted or referenced
  - No generic "typical" content without basis

- [ ] **Assumptions and gaps marked clearly**
  - All assumptions tagged: `[ASSUMPTION: ...]`
  - All clarifications needed tagged: `[CLARIFICATION NEEDED: ...]`
  - Contradictions noted: `[NOTE: ...]`

---

### Structure & Format

- [ ] **Document structure matches template**
  - All required sections present
  - Sections in correct order
  - Output matches `assets/as-is-output-template.md`

- [ ] **Executive Summary**
  - 150 words or fewer
  - Covers: process, stakeholders, top 3 challenges
  - Written in clear, business language

- [ ] **Stakeholder Matrix**
  - 5-10 stakeholders documented
  - Table format used
  - Columns: Role, Name, Responsibilities, Tools, Pain Points
  - All fields populated

- [ ] **AS-IS Process Flow**
  - 15-25 main process steps (not more, not fewer)
  - Each step has all required elements:
    - Actor
    - Trigger
    - Actions
    - Tools/Systems
    - Output
    - Time
    - Dependencies
    - Pain Points
  - Each step: 50-75 words
  - Sequential numbering (Step 1, 2, 3...)

- [ ] **Information Flow Analysis**
  - 200-300 words
  - Describes where data lives
  - Describes how data moves (or doesn't)
  - Identifies data quality issues

- [ ] **Challenges Summary Table**
  - 8-12 challenges identified (not more)
  - Table format used
  - Columns: Category, Issue, Impact, Frequency, Stakeholders
  - All fields populated
  - Prioritized (most important first)

- [ ] **Current State Metrics**
  - 5-8 baseline KPIs documented
  - Table format used
  - Even if rough estimates, captured
  - Measurement method noted

---

### Gap Analysis Quality

- [ ] **All 7 dimensions analyzed**
  - Visibility gaps
  - Speed/efficiency gaps
  - Data quality gaps
  - Communication gaps
  - Customer experience gaps
  - Scalability gaps
  - Reporting gaps

- [ ] **Gap tables complete**
  - 3-5 gaps per dimension
  - Total: 15-25 gaps across all dimensions
  - Each gap has:
    - Clear description
    - Business impact stated
    - HubSpot solution identified
  - Tables formatted consistently

- [ ] **Gaps prioritized**
  - Impact assessed (H/M/L) for each gap
  - Complexity assessed (H/M/L) for each gap
  - Priority matrix created
  - Categorized: Quick Wins, Core Improvements, Strategic

- [ ] **Quick Wins identified**
  - 3-5 Quick Wins called out
  - High Impact + Low Complexity
  - Specific and actionable

---

### Word Count & Length

- [ ] **Executive Summary: 150 words max**
- [ ] **Each process step: 50-75 words**
- [ ] **Information Flow Analysis: 200-300 words**
- [ ] **AS-IS Section total: 3,000-4,000 words**
- [ ] **Gap Analysis Section total: 2,000-3,000 words**
- [ ] **Overall document: 5,000-7,000 words**

**If over word count:** Cut ruthlessly. Quality > Quantity.

---

### Language & Style

- [ ] **Client terminology used**
  - Their exact language for processes
  - Their status names
  - Their role titles
  - Their system names

- [ ] **No jargon without explanation**
  - Technical terms defined
  - Acronyms spelled out on first use
  - HubSpot features described simply

- [ ] **Active, specific language**
  - Not: "There are issues with visibility"
  - Yes: "Recruitment Officers can't see inquiry pipeline status"

- [ ] **Direct quotes included**
  - At least 5-8 stakeholder quotes
  - Used to illustrate pain points
  - Quotation marks used
  - Attribution included (role)

- [ ] **No vague statements**
  - Not: "The process is often slow"
  - Yes: "Assignment takes 2-4 hours during batch processing"

---

### HubSpot Alignment

- [ ] **HubSpot context considered**
  - Gaps mapped to HubSpot capabilities
  - Solutions are realistic for HubSpot
  - Integration needs identified
  - Tier requirements noted (if relevant)

- [ ] **Automation opportunities flagged**
  - Manual processes identified for automation
  - Workflow opportunities noted
  - Email automation opportunities noted

- [ ] **Process mapped to HubSpot objects** (preliminary)
  - Contacts, Deals, Companies, Tickets
  - Pipeline stages conceptualized
  - Properties identified

---

### Completeness

- [ ] **Edge cases documented**
  - Exceptions to normal process noted
  - How unusual scenarios are handled
  - Frequency of edge cases indicated

- [ ] **Integration requirements identified**
  - All current systems listed
  - Integration criticality assessed
  - Data flow requirements noted

- [ ] **Stakeholder pain points comprehensive**
  - Each stakeholder's frustrations captured
  - Pain points tied to specific process steps
  - Impact quantified where possible

- [ ] **Baseline metrics established**
  - Current state performance documented
  - Even rough estimates captured
  - Measurement method noted
  - Creates foundation for TO-BE targets

---

### Logical Flow & Coherence

- [ ] **Process steps logical and sequential**
  - Steps follow natural flow
  - No orphan steps (everything connects)
  - Handoffs clear
  - Timeline realistic

- [ ] **Gaps tied to AS-IS**
  - Every gap has evidence in AS-IS section
  - No gaps appear out of nowhere
  - Gaps logically flow from pain points

- [ ] **Recommendations aligned with gaps**
  - Quick Wins address high-impact gaps
  - Core Improvements address critical gaps
  - Prioritization makes sense

---

### Professional Presentation

- [ ] **Formatting consistent**
  - Headers hierarchical (H1, H2, H3)
  - Tables formatted properly
  - Bullet points aligned
  - Markdown syntax correct

- [ ] **No typos or grammar errors**
  - Spell-checked
  - Grammar checked
  - Proper punctuation

- [ ] **Clear section breaks**
  - Each section distinct
  - Transitions smooth
  - Easy to navigate

- [ ] **Client name used**
  - Document title includes client name
  - Process name specified
  - Date included

---

## Final Verification Questions

Before delivering, ask yourself:

### Accuracy
1. **Is every statement in this document grounded in transcript evidence?**
   - If no → Remove or mark as assumption

2. **Have I invented any details not in the transcripts?**
   - If yes → Remove immediately

3. **Are all stakeholder names, roles, and quotes accurate?**
   - If unsure → Double-check transcripts

### Completeness
4. **Would a TO-BE designer have everything they need from this document?**
   - If no → What's missing?

5. **Are all 7 gap dimensions thoroughly analyzed?**
   - If no → Complete the analysis

6. **Have I identified enough Quick Wins to show early value?**
   - If no → Find 3-5 Quick Wins

### Conciseness
7. **Is this document within 5,000-7,000 words?**
   - If no → Cut aggressively

8. **Have I eliminated fluff and redundancy?**
   - If no → Edit down

9. **Is every word adding value?**
   - If no → Delete

### Clarity
10. **Would the client understand this without explanation?**
    - If no → Simplify language

11. **Are pain points specific and actionable?**
    - If no → Add specificity

12. **Is the value proposition clear (why HubSpot will help)?**
    - If no → Strengthen gap-solution connections

---

## Common Issues to Check For

### ❌ Red Flags

- [ ] No red flags present:
  - Generic "best practices" without client context
  - Vague language ("often," "usually," "sometimes")
  - Invented stakeholder quotes
  - Process steps without evidence
  - Gaps without AS-IS foundation
  - Solutions mentioned in AS-IS section (save for TO-BE)
  - Over word count limit
  - Missing required sections
  - No direct quotes from transcripts
  - Inconsistent terminology

If any red flags found: **STOP and fix before delivering.**

---

## Delivery Readiness

When all checkboxes are checked:

✅ **Document is ready for delivery**

Provide to user with summary:
- "Discovery analysis complete for [Client Name]"
- "Document includes AS-IS (15-25 steps) + Gap Analysis (15-25 gaps across 7 dimensions)"
- "Word count: [N] words"
- "Identified [N] Quick Wins for Phase 1"
- "Ready for TO-BE design phase with arkode-process-design skill"

---

## Post-Delivery

After delivering to user:

1. **Ask for feedback**
   - "Does this accurately reflect your discovery?"
   - "Any missing information or clarifications needed?"

2. **Iterate if needed**
   - User may have additional context
   - May need to add clarifications
   - May need to adjust priorities

3. **Prepare for next phase**
   - This document becomes input for arkode-process-design skill
   - User may want to review with client before proceeding

4. **Do NOT automatically proceed**
   - Wait for user to request TO-BE design
   - This skill's job is done

---

## Quality Standards Summary

**Excellent delivery has:**
- ✅ 100% evidence-based content
- ✅ 15-25 process steps with full detail
- ✅ 15-25 gaps across 7 dimensions
- ✅ 3-5 Quick Wins identified
- ✅ 5-8 stakeholder quotes
- ✅ 5,000-7,000 words (no more)
- ✅ Client terminology throughout
- ✅ Clear business impact stated
- ✅ HubSpot solutions aligned
- ✅ No assumptions without marking
- ✅ Professional formatting

**Deliverable is ready when all checkboxes above are checked.**
